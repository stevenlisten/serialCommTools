# T001 全面测试 · 用例分析（阶段 A）

> 日期：2026-08-02 ｜ 被测对象：serial-monitor.html（v0.5，52KB 单文件）
> 目标：功能测试 + 业务/操作合理性测试 + 静态/动态 + 边界/越界 + 极端数据 + 耦合/关联 + 错误路径，全面无遗漏，可全量回归

## 1. 功能盘点（14 个功能域）
| 域 | 功能 | 用户可操作点 |
|----|------|--------------|
| F1 端口 | 授权列表(getPorts)、选择(requestPort)、下拉切换、上次端口记忆 | 下拉框、选择…按钮 |
| F2 连接 | 连接/断开/重连、busy 防抖、异常断开、参数热更新重开 | 连接按钮 |
| F3 参数 | 波特率(列表+自定义)、数据位、停止位、校验、流控、编码 | 6 个下拉框 |
| F4 接收 | 文本行分帧、HEX 16 字节组、尾部冲刷、时间戳、自动滚动、暂停/恢复、清空、行数上限 | 模式切换、4 个开关、清空 |
| F5 编码 | UTF-8/GBK/Latin-1、多字节跨 chunk | 编码下拉 |
| F6 过滤 | 关键字高亮、大小写、仅匹配、实时重建 | 搜索框、Aa、仅匹配 |
| F7 报警 | 开关、多关键字、响铃+闪烁+标题、HEX 模式 | 报警开关、关键字框 |
| F8 发送 | 文本/HEX、CR/LF、快捷列表(增删/上限)、命令历史(上下/上限/持久化)、Ctrl+C/D | 输入框、发送、快捷区 |
| F9 导出 | .log 导出（含头部/时间戳）、模式感知 | 导出按钮 |
| F10 持久化 | localStorage 全量设置、损坏恢复 | 自动 |
| F11 状态显示 | 状态栏(连接/端口/参数/RX/TX/速率)、按钮状态机、空状态 | 自动 |
| F12 安全 | XSS 转义（数据与过滤词注入） | 自动 |
| F13 错误路径 | serial 缺失、requestPort 取消、open/read/write 失败、Storage 异常 | 自动 |
| F14 兼容 | Chrome/Edge、file:// | 运行环境 |

## 2. 测试维度（9 类）
| 维度 | 含义 | 典型问题 |
|------|------|----------|
| F 功能 | 单功能按预期工作 | 功能缺失/结果错误 |
| B 业务合理性 | 操作顺序/状态下操作是否符合用户预期 | 未连接能发送？清空语义？ |
| Bd 边界 | 合法值边界（0/1/上限/最小） | 空输入、1 字节、16 字节边界 |
| OoB 越界 | 非法值输入 | 负波特率、奇数 HEX、超上限 |
| Ext 极端数据 | 超大/超快/特殊数据 | 100KB 行、2MB 突发、全 0xFF |
| Cpl 耦合关联 | 功能组合/并发/状态机联动 | 暂停+过滤、双击竞态、热更新+收数 |
| Err 错误路径 | 异常与失败处理 | 打开失败、Storage 异常 |
| Sec 安全 | 注入与转义 | XSS、HTML 实体 |
| St 静态 | 代码/结构静态质量 | 语法、重复 ID |

## 3. 风险矩阵（高→低）
| 风险 | 涉及维度 | 影响 | 应对用例 |
|------|----------|------|----------|
| 连接竞态（双击/快速重连） | Cpl | 双连接/双读循环 | TC-103/104/108 |
| HEX 模式语义（混显/过滤/报警） | F/Cpl | 数据误读 | TC-305/306（已修） |
| 多字节编码跨 chunk | F/Bd | 中文乱码 | TC-401~405 |
| XSS 注入 | Sec | 脚本执行 | TC-1001/1002 |
| 大数据卡顿/内存 | Ext | 页面卡死 | TC-311/312/313/1305 |
| 错误路径恢复 | Err | 状态卡死 | TC-1101/1103/1006 |
| 导出与过滤/模式耦合 | Cpl | 导出不符预期 | TC-803/804/1207 |
| 持久化损坏 | Err | 启动崩溃 | TC-902 |
| 快捷/历史上限 | OoB | 数据溢出 | TC-707/711 |
| 长时间稳定性 | Ext | 泄漏/漂移 | TC-1306 |

## 4. 测试策略
- 自动化优先：注入式 E2E（tools/e2e_test.cjs，?test=1 虚拟串口）+ 真实链路（tools/realport_test.cjs，VSPE COM10/11）
- 静态检查：node --check、HTML 结构断言（重复 ID/必需元素）、XSS 注入断言
- 多轮循环：用例编写 -> 测试 -> 修复 -> 覆盖度分析 -> 补充用例（至少 3 轮）
- 覆盖度统计：每个 TC 映射到自动化断言组（T 编号），用例清单中记录状态
- 全量回归入口：node tools/run_full_tests.cjs（汇总三部分）
