# 记录：T001-003 环境准备（步骤 1）
- 时间：2026-08-02
- 任务：T001 串口侦听软件
- 步骤：步骤 1 环境准备（规则 7）
- 操作命令：见下
- 输入：计划 v0.2 环境需求（com0com + pyserial + playwright-core）
- 过程：
  1. 下载 com0com 3.0.0.0（SourceForge 需解析签名镜像地址）→ 静默安装到 C:\tools\com0com\（NSIS /S /D=）→ 驱动无法加载
  2. 诊断：sc query com0com 服务 STOPPED；Get-PnpDevice 显示 ROOT\COM0COM\0000 状态 Error，Problem=CM_PROB_UNSIGNED_DRIVER（Code 52）；sc start 错误 577 → **驱动测试签名被 Win11 拒绝**
  3. 事实核查（搜索）：com0com Code 52 在 Win11 为已知问题；社区推荐 VSPE（Eterlogic）
  4. 安装 VSPE 1.5.8.489（msiexec 静默，驱动安装成功：Eterlogic Virtual Serial Ports Bus = OK）
  5. 创建 Pair：CLI -create_device 在评估版受限；GUI 自动化（UIA + WM_COMMAND 1001 打开 New device 向导 → CB 消息选 Virtual Pair → COM10/COM11 → 完成 → WM_COMMAND 32803 启动仿真）→ COM10/COM11 出现
  6. 端口号变更：避开 com0com 残留占用的 COM5/6 → 用 COM10/11
  7. 回环验证：pyserial 3.5 安装后 COM10 写 → COM11 读 → PASS
  8. 安装 playwright-core 到 C:\tools\node-selftest\
  9. 清理：卸载 com0com、删除 System32 残留 inf/sys/cat、删除 C:\tools\com0com 残留目录；日志存档
- 输出：虚拟串口对 COM10↔COM11（VSPE）；pyserial 3.5；playwright-core
- 结果：✅ 完成（方案偏差：com0com→VSPE、COM5/6→COM10/11，已登记环境表与计划）
- 问题与结论：
  - 问题 1：com0com 驱动签名失败 → 结论：Win11 必须用签名驱动；VSPE 驱动签名有效
  - 问题 2：评估版禁用 CLI 创建设备 → 结论：WM_COMMAND 直接触发 GUI 向导可绕过 UIA 限制
  - 问题 3：UIA InvokePattern 对 VSPE 无效 → 结论：Win32 消息（WM_COMMAND/BM_CLICK/CB_*）可靠
