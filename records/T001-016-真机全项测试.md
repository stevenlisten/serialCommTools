## 发现并修复的真实缺陷
- **D8 [中] 串口流 done 结束未识别为断开**：2MB 突发后 VSPE 驱动以 done 收流，应用 readLoop 仅处理异常，读循环静默退出、界面假"已连接"、不再收数（TC-1306 实证 rx 冻结）
- 修复：readLoop 增加 streamEnded 检测 → onDisconnected('连接已断开（串口流结束）')
- 回归：注入式 E2E 209/209 无回归；真机全项 157/157 通过

## 环境实证（供后续复用）
1. VSPE getPorts 顺序不稳定 → 测试需 COM10 索引校准（连接+对端回读）
2. VSPE stop/start 后连接栈不可靠 → open 失败用"端口不存在"实构；异常断开/写失败注入式覆盖
3. 大数据后 VSPE Pair 会话损坏（done 收流）→ 应用 v0.6 正确识别；空闲测试移至 burst 前
4. 消费速率约 85KB/s → 2s flush 无法积累 2MB，自动日志轮转真实链路不可触发（注入式 T43 覆盖）
5. 同端口多客户端共享打开不稳定 → 端口切换用独占连接+对端回读
6. Chrome headed 启动会清空不完整结构的 serial_chooser_data → 测试前自动预检注入完整结构
