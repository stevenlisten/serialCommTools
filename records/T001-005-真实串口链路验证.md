# 记录：T001-005 真实串口链路验证（步骤 6 后半）
- 时间：2026-08-02
- 任务：T001 串口侦听软件
- 步骤：步骤 6（真实链路）
- 环境：VSPE 虚拟串口对 COM10<->COM11；Chrome 150 headless；Python 模拟设备（tools/serial_sim.py）
- 授权方案（关键经验）：
  1. Web Serial 的 requestPort() 必须用户手势 + 系统选择器，CDP/Playwright 无法自动化（已实测）
  2. Chrome 企业策略 SerialAllowAllPortsForUrls 实测未能跳过选择器
  3. 最终方案：把授权直接写入 profile Preferences 的 content_settings.exceptions.serial_chooser_data（键 file:///*,*，chosen-objects 含设备实例 ID ETERLOGIC_VSPE\ETERLOGIC_VSPE_PORT\COM10），getPorts() 即返回该端口，无需用户再授权（格式与用户浏览器现有记录一致）
- 测试结果（tools/realport_test.cjs）：11/11 通过
  - Python 模拟设备（COM11）-> 浏览器（COM10）收到：HELLO-FROM-SIM / 中文 UTF-8 / ALERT / 特殊字节 00 01 02 FE FF 0D 0A（HEX 模式）
  - 浏览器发送 PING-FROM-BROWSER+CRLF -> COM11 收到（模拟设备记录文件验证）
  - RX/TX 计数、HEX 尾部冲刷（不足 16 字节）、全程无控制台错误
- 期间发现并修复：HEX 模式尾部数据不足 16 字节不显示 -> 增加 300ms 定时冲刷
- Edge 150 兼容性加载验证通过（navigator.serial=object，无错误）
