## 1. 目标与验收标准（规则 3）

### 目标（一句话）
交付一个**单文件 HTML 串口侦听工具**：双击即可在 Chrome/Edge 中运行（file:// 协议），无后端、无构建、无外部依赖，实时侦听串口数据并支持日志留存；**界面美观，参考优秀设计**。

### 验收标准（可量化）
- [x] AC-1 双击 serial-monitor.html 以 file:// 打开，navigator.serial 可用（本机 Chrome 150 / Edge 150 已实证）
- [ ] AC-2 点击「连接」弹出系统端口选择器，可选择 COM10（VSPE 虚拟口）并成功打开（真实链路待授权验证；注入式已验证）
- [x] AC-3 串口参数可配置：波特率（常用列表 + 自定义）、数据位、停止位、校验位、流控、编码
- [x] AC-4 接收数据实时显示：ASCII/HEX 可切换，时间戳可开关，自动滚动/暂停/清空可用
- [x] AC-5 搜索过滤可用（关键字匹配并高亮，大小写可切换，可仅显示匹配行）
- [x] AC-6 日志可一键导出为 .log 文件（含时间戳）
- [x] AC-7 配置（端口、波特率等）写入 localStorage，刷新后保留
- [x] AC-8 断开（含异常断开）有状态提示，可一键重连
- [ ] AC-9 通过虚拟串口对（VSPE COM10/COM11）+ Python 模拟数据源完成全功能自测（真实链路待授权验证）
- [x] AC-10 单文件、离线可用、无 CDN、无构建依赖
- [x] AC-11 关键字报警（响铃 + 界面闪烁），功能有开关可随时开/关
- [x] AC-12 基础发送：HEX/ASCII 输入 + 快捷发送列表（可增删、持久化）
- [x] AC-13 UI 美观评审通过（暗色主题、清晰层级、状态可视化；对照优秀项目界面）

### 范围边界
- 做：侦听接收为主 + 基础发送；所有功能自行完整实现
- 不做：后端服务、Electron/PWA 打包、多协议解析/波形仪表盘（Serial-Studio 级别）、固件升级、蓝牙/MQTT 等非串口通道

### 步骤 3：串口核心（连接/参数/读循环）
- 小目标：能连 COM 并持续读数据
- 操作：requestPort()（用户手势）→ port.open(SerialOptions) → readable.getReader() 异步读循环 → 字节缓冲 → 事件分发；断开/取消读/关端口；异常处理；参数热更新（重开端口）
- 预期结果：连接虚拟串口一端无异常；数据进入缓冲区
- 验证方式：Python 端向另一端发送已知字节，JS 端收到
- ⏳ 实际执行结果：✅ 完成（2026-08-02）Web Serial 核心（连接/断开/重连/读循环/编码解码/异常捕获）已实现并通过注入式测试（T2/T16/T17）；修复 busy 状态未复位 Bug
- ✅ 审查/自测/验证/对比/修订记录：✅ E2E T2 连接、T16 断开重连、T17 异常断开全部通过

### 步骤 4：接收视图（ASCII/HEX/时间戳/滚动）
- 小目标：接收数据可视化
