## 3.3 Web Serial 关键模式（7 个，均经实证/修复验证，勿回退）
1. **file:// 可用**：file:// 下 isSecureContext=true，navigator.serial 可用（Chrome/Edge 150 实测）
2. **权限模型**：requestPort() 必须用户手势+系统选择器（无法自动化）；getPorts() 返回已授权端口（免手势）
3. **读循环**：readable.getReader() + TextDecoder(enc,{stream:true})；断线 reader.cancel()→port.close()
4. **解码器复用（v0.3）**：同编码跨重连复用 TextDecoder 实例，保留多字节流状态；编码变化才重建
5. **BOM 剥离（v0.3）**：解码文本全局移除 U+FEFF（单块/跨块/流中重复）
6. **持久 writer（v0.5）**：连接期持有单一 writer，write 由流内部排队；断开先 releaseLock 再 close（防锁冲突）
7. **参数热更新**：连接中改参数 → disconnect(true)+connect(同 port 对象) 重开，历史保留

## 3.4 业务决策清单（改功能前先读，勿擅自变更语义）
1. 孤立 CR 视为换行（
 与 
 均换行）；HEX 模式始终显示原始字节
2. 过滤/仅匹配只作用于数据行；系统提示行（已连接/断开）始终显示
3. 日志导出为全量会话（过滤不影响导出）；导出按 entry.kind 自适应 txt/hex，TX 带 → 标记
4. 清空 = 会话重置（视图+日志+计数+暂停缓存+速率基准全清）
5. 命令历史：相邻去重、上限 50 条保留最新、持久化
6. 快捷发送：上限 12 条、拒绝重复、增删持久化
7. 报警只针对接收数据（TX 不触发）；报警词按 includes 文本匹配（非正则）
8. 写失败/读异常视为连接异常：提示并断开，可一键重连
9. 双击连接/断开有 busy 防竞态；端口切换必须经下拉选择
10. 自动日志：连接开始、断开收尾；每段 2MB 轮转（_001/_002）；2s 落盘；每条独立一行
11. HEX 模式只显示字节组，解码文本仅用于报警检查（不渲染，防混显）
12. BOM 视为格式字符一律剥离

## 3.5 已知边界与限制（诚实清单）
- Web Serial 不暴露 COM 端口号：USB 设备显示 USB#xxxx:yyyy，虚拟口显示「串口 #n」
- requestPort 系统选择器无法自动化：测试用 profile 注入授权（见 M004）
- showDirectoryPicker 需用户手势；不支持时自动回退浏览器下载目录（按段下载）
- Firefox 需 151+；Safari/移动浏览器不支持
- localStorage 存配置：清理浏览器数据会清除；自动日志目录句柄不跨会话持久（每次需重选）
- 自动日志关闭页面瞬间最多丢 ~2s 缓存（每 2s 落盘）
- VSPE 评估版限制：5 设备上限、重启后虚拟串口对需重建（见 M005）

## 4.3 虚拟串口对（M005 核心结论）
- **Win11 下 com0com 驱动不可用**（测试签名，Code 52）→ 必须用 **VSPE**（签名驱动）
- 创建：VSPE GUI → Create new device → Virtual Pair → COM10/COM11 → Start emulation
  （CLI -create_device 评估版受限；自动化用 WM_COMMAND 1001 打开向导，详见 M005）
- 回环验证：`python -c "import serial; a=serial.Serial('COM10'); b=serial.Serial('COM11'); a.write(b'PING'); assert b.read(4)==b'PING'"`
- ⚠️ VSPE 评估版：上限 5 设备、重启后虚拟串口对需重建（按 M005 重建即可）

## 4.4 浏览器授权注入（M004 核心结论，真实链路测试免人工授权）
1. 获取设备实例 ID：`Get-PnpDevice | Where-Object {$_.FriendlyName -match 'COM10'}` → InstanceId（如 ETERLOGIC_VSPE\ETERLOGIC_VSPE_PORT\COM10）
2. 写入 profile 的 `Default\Preferences`：`profile.content_settings.exceptions.serial_chooser_data["file:///*,*"] = {last_modified, setting:{chosen-objects:[{device_instance_id, name}]}}`
3. 之后同 profile 启动 headless Chrome，`getPorts()` 即返回该端口（免系统弹窗）
- 注意事项：改 Preferences 前必须关闭该 profile 的 Chrome 进程；JSON 保持合法

| 发送 | 100KB 单次；180KB+紧跟；50 次并发 | 持久 writer 排队 | T33/T45 |
| 未完成行更新 | rAF 节流（每帧最多 1 次 DOM 写） | pendingScheduled 标志 | T23/T40 隐式 |
| 过滤重建 | 输入防抖 350ms + 重建 | rebuildView | T31/T6 |
| 单文件体积 | ~61KB（v0.5） | 无外部依赖 | - |

## 性能防护原则
1. 渲染路径禁止同步大循环建 DOM（用 rAF 批量/字符串拼接）
2. 内存有上限：DOM 6000 / 日志 20000 / 自动日志 2MB 段
3. 高频路径（onBytes）保持 O(n)，避免正则重开销（BOM 剥离用 indexOf 快速路径）
4. 新增功能若引入定时器/流，参照 AutoLog：断开必清理
